## Test-Broken Flag ⚠️

**All 5 RTM navigation failures share an identical pattern that strongly suggests the test — not the application — is the problem:**

| Scenario | Pattern |
|---|---|
| Navigate to the Dashboard page | Given passes (~250ms) → When exceeds exactly 5000ms |
| Navigate to the Accounts page | Given passes (~250ms) → When exceeds exactly 5000ms |
| Navigate to the Move Money page | Given passes (~400ms) → When exceeds exactly 5000ms |
| Navigate to the Transactions page | Given passes (~250ms) → When exceeds exactly 5000ms |
| Navigate to the Cards page | Given passes (~250ms) → When exceeds exactly 5000ms |

- In every scenario the `Given` (home page load) passes quickly and consistently — the app is reachable.
- Every `When` step (tab click + URL confirmation) burns the **entire** 5000ms Cucumber step budget and is cut off, on all 5 tabs, every time.
- The uniformity (same step nature, same exact 5000ms cutoff, same tab-click action) points to a **test-side defect**: a missing/incorrect wait (e.g. `waitForURL` never matching), a stale/incorrect locator, or a race condition in the tab-click step — **not** a genuine application regression.
- **Flag: test-broken (suspected missing wait / stale locator / race condition in the tab-click step).** Self-Healing Test Healer should inspect `step-definitions` / page objects for the navigation `When` step before assuming the app regressed.

Additionally, the `navigation-suggested.feature` scenario contains an undefined step (`Then I see the Cards page content, confirmed by URL`) — that is a missing step definition, a test-code gap (flagged for Self-Healing Test Healer), not an application issue.
